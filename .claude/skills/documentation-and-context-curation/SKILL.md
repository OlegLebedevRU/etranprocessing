# Documentation and context curation

1. Обновляй docs при наблюдаемом, протокольном, архитектурном или эксплуатационном
   изменении; не превращай каждую внутреннюю правку в новый документ.
2. Для активного docs файла используй `{сфера}_{флоу}-{дескриптивное-имя}.md`
   по [конвенции](../../../docs/etran_dev-documentation-naming-convention.md)
   и сразу добавь ссылку в docs/README.md. Skills и context используют свой индекс.
3. Карточка содержит роль, границы, контракты, инварианты, state machine, исходники,
   проверки, риски и источники/дату. [Шаблон](../../../.agent-context/templates/distillate-template.md).
4. Не копируй документацию целиком: цель — одна карточка до ~100 строк и skill до ~60.
   Ссылки на первичные источники, отдельно code/document/requirement/runtime evidence.
5. Не переноси секреты, приватные URLs или сырые логи. При обнаружении опубликованной
   авторизации убери пример и передай владельцу необходимость оценки/ротации,
   не заявляй выполненную ротацию без evidence.
6. После сложной задачи обнови затронутую карточку, дату/ревизию и оставшиеся риски;
   длинные одноразовые отчёты — docs/history, краткий итог — completed handoff.
7. Проверь относительные ссылки, naming, обязательные разделы и индексы.
   Doc-only не требует pytest/ruff/pyright/npm/native build.

## Результат
Согласованные docs/index/distillate/handoff и статус проверки ссылок.
[Регламент ревизии](../../../docs/etran_dev-agent-context-workflow.md) определяет
когда карточка устарела; дата чтения сама по себе не подтверждает runtime.
