# Verification matrix

1. Определи изменённый scope и ограничения запуска из AGENTS.md и запроса.
   Для doc-only не запускай pytest, ruff, pyright, frontend или native build.
2. Используй [матрицу](../../../.agent-context/operations/validation-matrix.md):
   выбери happy, negative, retry/duplicate, restart paths и downstream-потребителей.
3. Для бага подготовь воспроизведение до исправления и повтори после; для новой
   функциональности добавь проверки core/invalid/edge; для refactor найди покрытие.
4. Cross-stack: сначала локальные слои, затем цепочка. Нельзя объявлять E2E по
   компиляции, PUBACK, синтетическому stream_event или локальному UI-флагу.
5. Не скрывай ошибки исключением тестов или ослаблением assertions. Зафиксируй
   блокировки окружения и оставшийся риск; невыполненная проверка не является успешной.

## Обязательный результат
| Проверка / слой | Ожидается | Факт / evidence | Статус | Причина пропуска / риск |
|---|---|---|---|---|
| | | | passed / failed / not run / N/A | |

Указывай команду, окружение, код возврата, время UTC, версии и обезличенные correlation IDs.
Подробные логи оставляй в разрешённом артефакте, в handoff — только ссылки и выводы.
