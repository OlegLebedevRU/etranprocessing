# Административный карантин MQTT

Раздел MenuBuilder «Администрирование → MQTT-подключения» предназначен для суперпользователей. Источник отказов — docker logs RabbitMQ. При запуске observer строит окно до суток из доступного журнала, затем следует за потоком с курсором. Логин при отказе не удостоверяет личность. Активные соседи за IP определяются выборкой list_mqtt_connections; короткие сессии между выборками могут быть пропущены. Остановка наблюдателя сокращает доступную историю соседей. Данные наблюдения хранятся в памяти и атомарно публикуются в /run. У MB нет Docker socket.

## Установка

1. Выпустить backend MenuBuilder, понимающий ревизии 036 и 037. Затем миграцией ProcessingBackend установить 037. Таблица mqtt_quarantine_operations содержит идемпотентные административные решения. Выпустить frontend после активации исполнителя.
2. На Linux с Python 3.12+, nft и iproute2 скопировать collector.py и edge.py из принятого коммита в /opt/mb-mqtt, два unit-файла — в /etc/systemd/system. До активации проверить netns_smoke.py через sudo unshare --net. Тест создаёт собственный сетевой namespace.
3. В /etc/mb-mqtt-edge.conf задать MQTT_EXTERNAL_INTERFACE и MQTT_PROTECTED_NETWORKS (пробелами, CIDR адреса площадки, мониторинга и администраторов). Только собственная таблица inet mb_mqtt. Включить mb-mqtt-observer.service и mb-mqtt-edge.service, затем добавить compose.yaml из этого каталога к действующим overlays MenuBuilder. Проверить оба новых read-only mount и прежние mounts/env.
4. Проверить свежесть наблюдения, superuser/403, предпросмотр соседей, журнал и отсутствие активных правил при первой установке. Проверка рабочего firewall с живым клиентом требует выбора его IP. Никакие адреса не блокируются по порогу автоматически.

## Бессрочная блокировка

Режим «До ручного снятия» создаёт элемент nftables без таймера. Контракт использует −1 для бессрочного решения и 0 для снятия. Исполнитель восстанавливает бессрочные записи из локального состояния после запуска. Предпросмотр, подтверждение влияния на общий IP, защита инфраструктурных адресов и аудит действуют для обоих типов блокировки. Перед откатом на версию без поддержки −1 снимите бессрочные правила через интерфейс.

## Восстановление

Истечение TTL выполняет ядро. Решения сначала сохраняются в Etran, исполнитель фиксирует последнюю версию для каждого IP в /var/lib/mb-mqtt-edge. После перезагрузки восстанавливается остаток срока, а очередной запуск MB повторяет доставку незавершённых решений. Перед возвратом предыдущего релиза снять активные правила через UI, проверить фактическое состояние, убрать два mounts, отключить units. Удалять только отдельную таблицу inet mb_mqtt. При возврате MB на предшествующий 037 образ проверить его schema compatibility. Историю решений и локальную версию исполнителя сохранять при обновлениях.
