# PROMPT AGENT — шаг 5 / задание 2: новый `tools/l4setup` — единый Zero-Touch инсталлятор `l4setup.exe` (Этап 1, без самообновления)

Ты Senior Windows/C Systems инженер: C/Win32, MSVC `/MT`, x86-bootstrapper для x86/x64 ОС от Windows 7 SP1, SCM, UAC, miniz, WinHTTP, CryptoAPI. Разрешенный проект — новый `tools/l4setup` (`src/`, `res/`, `build.cmd`, `tests/`, `README.md`, `CHANGELOG.md`). Из `tools/l4superv/src/installer_main.c`, `zip_extractor.c`, `service_mgr.c`, `miniz.c` разрешено **копировать/переиспользовать код** (или подключать `.c` по относительному пути), но не менять их. `tools/l4pin/src/cert_discovery.c/.h` (задание 1) подключается как есть. Не трогать `l4superv`-логику оркестратора (задание 3), backend/frontend, `deploy/`.

Прочитай [общий overview](prompt_step5_stacks_overview.md): разделы 2.1, 2.3, 4.1–4.4 (контракты — обязательны), 5 (стенд), 6 (владелец). План: `docs/term_tool-zero-touch-installer-and-remote-runtime-plan.md`, разделы 3.2 (S1–S10), 4.2–4.3, Пакеты 1–4.

## 1. Факты

- Текущий `l4install` (`installer_main.c`): распаковка `tools.zip` + `ffmpeg.zip` (miniz) в `%dest%`, создание подкаталогов `l4sql l4pin l4con l4superv l4desk ffmpeg`, PATH через `HKLM\...\Environment` + `WM_SETTINGCHANGE`, регистрация служб `Leo4Proxy`, `mosquitto`, `L4Con`, `L4Superv` (имена — сверить по `service_mgr.c` и `Get-Service` на стенде: `Leo4Proxy`, `mosquitto`, `L4Con`, `L4Superv`), проверка активного стрима блокирует установку. С сертификатом не работает.
- Стенд — Windows x64, `C:\l4tools` с работающими службами и валидным сертификатом (S3 + S9). `l4superv.json`: `watchdog_interval_sec: 10`, `mosquitto_port: 1883`, `auto_reset_on_clone: true`, `services.{leo4proxy,mosquitto,l4con}.auto_start: true`. `state.json`: `status: active`, `sn`, `thumbprint`, `hw_fingerprint`, `installer_base_path`.
- `leo4proxy` слушает `127.0.0.1:18443` (`/_leo4/info`), `127.0.0.1:18883`; mosquitto — `1883`. `l4superv` запускает `l4desk` в интерактивной сессии только при `status == active`.
- Payload для Этапа 1 собирается заданием 4 (`build_dist.cmd`): два архива `payload_x86.bin`, `payload_x64.bin` линкуются в `l4setup.exe` как `RT_RCDATA` с именами `PAYLOAD_X86`, `PAYLOAD_X64`. До готовности задания 4 для разработки использовать `tools/dist/tools.zip` + `tools/dist/ffmpeg.zip` через флаг разработчика `--payload-dir <DIR>` (не документировать для инженеров).
- Windows 7 x86: ОС не запустит x64 PE — поэтому bootstrapper строго 32-битный, `/SUBSYSTEM:WINDOWS,6.01`, консольный вывод через `AttachConsole(ATTACH_PARENT_PROCESS)` при наличии родительской консоли.

## 2. Задачи

1. **Проект и CLI (Пакет 1):** `tools/l4setup/src/main.c` — парсер флагов по 4.2 overview (`--pin/-p`, `--force-reissue`, `--no-pin`, `--silent`//S, `--dest/-d`, `--repair`, `--smoke-only`, `--version`, dev-`--payload-dir`). `res/l4setup.rc`: `VERSIONINFO` (версия из `version.h`, подставляется заданием 4), манифест `requireAdministrator` **не** ставить — elevation делается вручную (п. 2), чтобы обычный запуск мог показать понятную ошибку `20`.
2. **UAC Elevation Manager (Пакет 2.1):** проверка `TokenElevationTypeFull`/`TokenElevation`; при отсутствии — `ShellExecuteExW(runas)` с теми же аргументами, ожидание дочернего, проброс его кода возврата; отказ UAC → код `20`.
3. **Preflight (Пакет 2):** детекция ОС/битности (`IsWow64Process`, `RtlGetVersion`), отказ `21` для ОС < 6.1; Win7 → ветки реестра TLS 1.2 (`SCHANNEL\Protocols\TLS 1.2\Client`, `DisabledByDefault=0`, `Enabled=1`) — только запись, без перезагрузки; проверка `ucrtbase.dll` → предупреждение в `warnings`. Firewall: правила для `%dest%\**\*.exe` и loopback-портов через `netsh advfirewall` (или INetFwPolicy2), идемпотентно по имени правила `L4Tools-*`.
4. **Drainage (Пакет 2.2):** для служб `Leo4Proxy`, `mosquitto`, `L4Con`, `L4Superv`: `QueryServiceStatusEx` → `ControlService(STOP)` → ожидание 5 с → `TerminateProcess` по `dwProcessId`; завершение осиротевших `ffmpeg.exe`, `l4desk.exe`, только если их путь начинается с `%dest%` (не убивать чужие `ffmpeg.exe`); освобождение портов `1883`, `18443`, `18883` (владельца определять через `GetExtendedTcpTable`, убивать только процессы из `%dest%`). Если активный стрим (`ffmpeg_state.json`/процесс `ffmpeg.exe` из `%dest%`) — без `--silent` спросить, с `--silent` — прервать с кодом `22` и `warnings: ["active_stream"]`. Провал → `22`.
5. **Распаковка и службы (Пакеты 1, 2):** выбор `PAYLOAD_X64`/`PAYLOAD_X86` по ОС; распаковка во временный `%dest%\.staging-<pid>\`, затем атомарная замена подкаталогов (`MoveFileExW` с `MOVEFILE_REPLACE_EXISTING`), старые — в `%dest%\rollback\<prev_version>\` (хранить одну предыдущую). Сохранить пользовательские файлы: `l4superv.json`, `state.json`, `mosquitto.conf`, логи, `pending_pin.json`. PATH и регистрация служб — переиспользовать код `installer_main.c`/`service_mgr.c`; перерегистрировать службу, только если путь бинарника отличается. Провалы → `23`/`24`.
6. **Фаза 3 — сертификат (Пакет 3, S9/S10, ключевое требование):**
   - `expected_sn` = `state.json.sn`, если файл есть и `hw_fingerprint` совпадает с текущим (переиспользовать алгоритм `hardware_fingerprint.c` только для чтения; при несовпадении — S5: `expected_sn = NULL`, предупреждение `hw_fingerprint_changed`, сертификат **всё равно не удалять** в Этапе 1 — этим займется `l4superv` по своей политике).
   - `cert_discover(expected_sn)`: `CERT_VALID` → `cert.reused = true`, PIN не спрашивать; переданный `--pin` без `--force-reissue` → `warnings: ["cert_reused_pin_ignored"]`, к CA не ходить. `CERT_VALID`/`CERT_EXPIRING` + `--force-reissue --pin` → выпуск. `CERT_EXPIRING` без флага → предупреждение `cert_expiring`, reuse. `CERT_BROKEN`/`CERT_ABSENT` → нужен PIN.
   - Нужен PIN, есть `--pin` → запуск `%dest%\l4pin\l4pin.exe [--force] <PIN>` (stdout в лог с маскировкой `pin=`), 3 попытки с backoff 2/4/8 с только при сетевых ошибках; PIN отклонен CA → `25`. CA недоступен после 3 попыток → записать `pending_pin.json` по 4.4 (DPAPI machine, ACL SYSTEM+Administrators, TTL 72 ч) → `status = ready_for_online`, код `11`.
   - Нужен PIN, нет `--pin`: GUI-режим → компактный диалог (DialogBox, поле PIN, кнопки «Установить», «Пропустить — ввести позже»); `--silent`/`--no-pin`/«Пропустить» → `status = standby_waiting_pin`, код `10`, службы остаются запущенными (l4superv сам ждет — задание 3).
   - После успешного выпуска — `ControlService(L4Superv, 128)`; ожидание `_leo4/info.status == ready` до 15 с, иначе `26`.
   - PIN держать в памяти минимально, `SecureZeroMemory` после использования; в аргументах дочернего процесса PIN неизбежен — не писать командную строку в лог.
7. **Фаза 4–5 (Пакет 4):** старт служб в порядке `Leo4Proxy → mosquitto → L4Con → L4Superv`; probes: `GET 127.0.0.1:18443/_leo4/info` (WinHTTP, 5 с), `connect 127.0.0.1:1883`, `l4desk.exe` в сессии `WTSGetActiveConsoleSessionId()` (только если `active`), `ffmpeg.exe -f gdigrab -i desktop -frames:v 1 -f null -` с таймаутом 10 с (в сессии 0 gdigrab может не видеть десктоп — тогда `skipped`, не `fail`), `desktop_locked` через `WTSQuerySessionInformation`/`OpenInputDesktop`. Критичные: `proxy_info`, `mosquitto_port`; остальные — предупреждения → код `12`.
8. **`install_summary.json`** по 4.3 (кодировка UTF-8 без BOM, атомарная запись через временный файл); лог `%dest%\l4setup.log` (append, с датой, без PIN). В `state.json` записать `installed_version`, `installer_summary_path` (через полную перезапись JSON недопустимо — только точечное добавление/обновление ключей, сохраняя остальные; при отсутствии JSON-парсера в проекте — минимальный безопасный патч строкой или отдельный `installed_version.json`, согласовать с заданием 3 через overview).
9. **Идемпотентность:** если `state.json.installed_version == VERSIONINFO` и бинарники на месте и нет `--repair` — пропустить фазы 1.4–2 (drainage/распаковка/службы), выполнить только 3–5. Повторный `l4setup.exe --pin <PIN>` на standby-терминале — ровно этот путь.
10. `README.md` + `CHANGELOG.md` проекта: фазы, флаги, коды возврата, формат summary, известные ограничения (нет Authenticode, `--from-registry` — Этап 2).

## 3. Проверки

- Сборка `cmd /c build.cmd` из `tools/l4setup` → один `bin\l4setup.exe` (x86), `/MT`, без предупреждений; `l4setup.exe --version` печатает версию и выходит `0` без UAC.
- Unit-тесты (`tests/`): парсер CLI (все комбинации `--pin/--no-pin/--silent/--force-reissue`), выбор payload по архитектуре, машина состояний фазы 3 (таблица: cert_state × pin_given × force × ca_reachable → действие/код), сериализация `install_summary.json`, маскировка PIN в логах. Запуск `cmd /c run_tests.cmd`.
- Стенд (эта машина) — строго по протоколу раздела 5 overview, **после подтверждения владельца**:
  1. Снимок «до» (thumbprint `CC88419A…`, `_leo4/info`, службы, бэкап `state.json`, `l4superv.json`).
  2. `l4setup.exe --silent --payload-dir tools\dist` (или с встроенным payload, если задание 4 готово) → код `0`, `cert.reused == true`, thumbprint не изменился, `_leo4/info.status == ready`, 4 службы `Running`, `l4desk.exe` в интерактивной сессии, `install_summary.json` валиден.
  3. `l4setup.exe --silent --pin 000000` → код `0`, `warnings` содержит `cert_reused_pin_ignored`, в логе нет запуска `l4pin` с PIN.
  4. Повторный `l4setup.exe --silent` → код `0`, `LastWriteTime` бинарников не изменился (идемпотентность).
  5. `l4setup.exe --smoke-only` → код `0`/`12`, summary обновлен.
  6. **[владелец]** MenuBuilder UI: `online`, трансляция, удаленный ввод.
  7. S10 (`CERT_ABSENT`): только на ВМ или после явного согласия владельца на `--force-reissue` с новым PIN; иначе — покрыть unit-тестами машины состояний и зафиксировать «не проверено на реальном стенде».
- Негатив на стенде без риска: запуск без прав администратора с отменой UAC → код `20`; `--dest D:\nonexistent\readonly` → `23`; `--silent` при искусственно занятом порте 1883 посторонним процессом (например, `python -m http.server 1883` от владельца) → `22`, чужой процесс **не убит**.
