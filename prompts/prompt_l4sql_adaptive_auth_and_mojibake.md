# Техническое задание: Адаптивный конвейер аутентификации и устранение Mojibake в l4sql

---

## 1. Роль и контекст задачи

Ты — ведущий разработчик системного ПО для Windows (C / Win32 / MS SQL Server ODBC).
Твоя цель — обеспечить надёжный доступ к базе данных терминала (`Postomat`, `Terminal`) для утилиты **`l4sql`** при её удалённом вызове через системную веб-консоль **`l4con`**, а также полностью устранить искажение кодировки русских символов (Mojibake) в диагностических сообщениях и данных таблиц.

### Исходная проблема
1. Служба `l4con` выполняется как служба Windows в `Session 0` под учётной записью `NT AUTHORITY\SYSTEM`.
2. При вызове `l4sql tb_Devices` через `l4con` дочерний процесс запускается под `NT AUTHORITY\SYSTEM`.
3. MS SQL Server (`(local)\sqlexpress`) настроен на аутентификацию Windows для локального пользователя киоска (`user` или `Administrator`). У учётной записи `NT AUTHORITY\SYSTEM` нет пользователя или прав в целевой базе данных `Postomat`.
4. В результате SQL Server возвращает ошибку:
   `[42000] (Error 4060): Cannot open database "Postomat" requested by the login. The login failed.`
5. Из-за несоответствия кодировки консоли (`CP_UTF8`) и ANSI-вызовов ODBC (`SQLGetDiagRecA`, `SQLGetData` с `SQL_C_CHAR`) текст ошибки и русскоязычные данные таблиц выводятся в виде кракозябр (`═х єфрхЄё...` или `???`).

---

## 2. Архитектурные требования к решению

1. **Изоляция и автономность**:
   - Решение реализуется непосредственно в `tools/l4sql` (модули `auth_adaptive.c`, `auth_adaptive.h`, `db_odbc.c`, `output_formatter.c`, `main.c`).
   - Не вносить превентивных настроек в инсталлятор `l4setup`.
2. **Адаптивный уровень доступа (In-Process Token Impersonation)**:
   - При запуске `l4sql` выполняет прямое подключение.
   - Если прямое подключение завершилось ошибкой 4060/18456 или процесс запущен под `NT AUTHORITY\SYSTEM`:
     - Определяется активная интерактивная сессия киоска (`WTSGetActiveConsoleSessionId`).
     - Запрашивается токен пользователя (`WTSQueryUserToken`).
     - Для Windows 10 извлекается связанный административный токен (`TokenLinkedToken` / High IL), гарантирующий активацию группы `BUILTIN\Administrators` при включённом UAC.
     - Вызывающий поток временно имперсонирует пользователя (`ImpersonateLoggedOnUser`), повторно выполняет подключение к БД, после чего возвращает контекст (`RevertToSelf`).
3. **Кросс-языковое самовосстановление прав (`-G, --grant-system-access`)**:
   - Добавить в `l4sql` служебный флаг `-G, --grant-system-access`.
   - При его вызове утилита подключается (включая адаптивную имперсонацию) и выполняет идемпотентный пакет T-SQL, выдающий права `db_datareader` для системной учётной записи.
   - Имя учётной записи должно определяться по бинарному SID `0x010100000000000512000000` (`S-1-5-18`) через `SUSER_SNAME()`, что обеспечивает корректную работу как на русской Windows (`NT AUTHORITY\СИСТЕМА`), так и на английской (`NT AUTHORITY\SYSTEM`).
   - Для добавления в роль базы данных использовать процедуру `sp_addrolemember` для обратной совместимости с MS SQL Server 2008 (Windows 7 SP1) и новее.
4. **Устранение Mojibake и поддержка UTF-8**:
   - Диагностические сообщения ODBC извлекать через `SQLGetDiagRecW` и конвертировать в UTF-8 (`WideCharToMultiByte(CP_UTF8, ...)`).
   - Имена колонок определять через `SQLDescribeColW` с конвертацией в UTF-8.
   - Данные ячеек извлекать через `SQLGetData` с флагом `SQL_C_WCHAR` с конвертацией в UTF-8.
   - В `output_formatter.c` вычислять ширину колонок по реальному количеству символов UTF-8 (`utf8_char_count`), а усечение строк производить безопасно по границам кодовых точек (`utf8_safe_copy`), исключая разрыв многобайтовых символов.

## 3. Инструкция по сборке, развёртыванию и эксплуатации

### 3.1. Сборка бинарников
Компиляция осуществляется скриптом `build.cmd` в каталоге `tools/l4sql`:
```cmd
cd tools\l4sql
build.cmd all
```
Скрипт собирает:
- `bin\x86\l4sql.exe` — универсальный 32-битный статический бинарник (совместим с Windows 7 SP1 и выше).
- `bin\x64\l4sql.exe` — 64-битный статический бинарник.
- `bin\l4sql.exe` — копия универсального x86 бинарника по умолчанию.

### 3.2. Эксплуатация через удалённую веб-консоль `l4con`

1. **Стандартный запрос данных**:
   ```cmd
   l4sql tb_Variables
   ```
   *Поведение*: `l4sql` запускается из-под `NT AUTHORITY\SYSTEM`. При получении ошибки доступа 4060 утилита автоматически перехватывает токен интерактивного пользователя (`user` / `Administrator`), выполняет подключение и возвращает таблицу с корректными русскими символами.

2. **Запрос с лимитом и в формате JSON**:
   ```cmd
   l4sql --limit 10 --json tb_Variables
   ```
   Возвращает валидный JSON-массив с UTF-8 кодировкой.

3. **Запрос в формате CSV**:
   ```cmd
   l4sql --limit 20 --csv tb_Counters
   ```

4. **Самовосстановление постоянного прямого доступа (Self-Provisioning)**:
   ```cmd
   l4sql -G
   ```
   или с подробным логированием:
   ```cmd
   l4sql -v -G
   ```
   *Результат*:
   `[OK] Successfully granted NT AUTHORITY\SYSTEM db_datareader rights to database 'Terminal'.`
   После выполнения этой команды системная учётная запись получает прямой доступ на чтение, и все последующие обращения выполняются напрямую без накладных расходов на имперсонацию.

5. **Диагностический режим**:
   ```cmd
   l4sql -v tb_Variables
   ```
   В логе отображается процесс автообнаружения БД, попытка прямого подключения и, при необходимости, этапы адаптивной эскалации токена.
