## Блокирующее несоответствие

`H-L4D-13-MB-v1` включает артефакт `nginx-configs/port_3000.conf`.
Регистрация даёт read grant только на commit
`f5017615a8a84eee318a78b54a992ceb45f91edc`. Для этих Git bytes:

| Источник | SHA-256 |
|---|---|
| Принятый handoff, historical | `e76037bdee1d28411ff843d6ee8dc3e0e8dff3c95382e2e972566afda1f6ef0d` |
| Grant commit, Git/raw | `d99f2bb62ba67f796b2c104bafd81fb63a6e2b50fc355aaf8dbf9c12f6930399` |
| Grant commit, только LF → CRLF | `fdf0a4e2b22383421754d0155c8b6dbe7eb946089aedd42a966e22cc6f923165` |

Ни raw, ни CRLF не совпадают с принятым SHA-256. Binding
`B-L4D-13-MB-GIT-v1` не содержит этот путь, поэтому использовать его
для данного файла нельзя. В принятом handoff указан отдельный
`report_commit: 4a6e124d870e06a2001a83464af2beb0123639b5`, но текущий
read grant **не разрешает** чтение внешнего файла из этого commit.
Предположение о правильном commit не заменяет разрешённую проверку.

## Результат и передача контроллеру

До обнаруженного несовпадения совпали метаданные prompt/registration,
sequence gate 17D и доступные проверенные артефакты предыдущих входов.
Проверка остальных артефактов немедленно прекращена по §1.6 и §2
`PROMPT-STANDARD.md`; полный gate не завершён. Тесты, сборка, runtime
smoke, финансовая сверка и deploy не запускались. Candidate handoff не
создавался. Rollback не требуется.

Контроллеру нужен новый точный адресный допуск по §8.5: сначала отзыв
`R-L4D-17E-MB-FIX-01-v1`, затем новая регистрация с проверенным commit
для этого артефакта и, если требуется, новым byte binding. Прежние
принятые handoff и данный report не править задним числом. После
публикации исправленного пакета повторить gate с начала.
