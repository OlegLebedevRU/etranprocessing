# Changelog — MenuBuilder

Значимые изменения административного backend и пользовательского web-интерфейса. Журнал фиксирует доступные возможности в их итоговом виде.

## Unreleased

### Added (2026-09-29)

- В области удалённого управления F8 и кнопка «Удержать курсор» приостанавливают локальную передачу перемещения, кликов и клавиш; повторное нажатие возобновляет ввод. При выходе из управления пауза сбрасывается.

### Added

- Суперпользователь задаёт для организации доступ к Classic, L4Desk или обеим версиям, версию по умолчанию и видимость страницы лицензий отдельно в каждой версии. Прежнее поведение сохранено для организаций без явного выбора.
- Редактирование адреса, примечания и часового пояса терминала доступно из списка L4Desk через ту же форму и API, что в Classic.
- Список терминалов L4Desk получил поиск по SN/адресу/названию, фильтр по номерам и диапазонам, сортировку по последнему выданному PIN и другим полям, а также пагинацию над таблицей; терминалы после первой сотни теперь доступны.
- L4mcp v1 выдаёт ролям 1, 3 и 5 собственные API-токены на странице MCP, проверяет выбранный терминал и `svc_online` перед короткой консольной командой и использует штатный учёт console-сессии.
- MCP-инструменты показывают состояния сертификатов и PIN по точным номерам или ограниченному диапазону, выдают не более пяти PIN за вызов через действующую политику биллинга.
- В онбординге выбирается платформа Windows, Linux или ESP32; тег `sys` сохраняется при повторной попытке подключения.
- Владелец L4Desk может получить новый PIN для своего терминала и скопировать ещё не активированный код прямо из списка. Повтор после сетевой ошибки и перезагрузки страницы использует ту же операцию.

- Изолированный E2E-контур может проверить отказ после адресного лимита бесплатных минут без платежа; для остальных tenant штатный лимит 120 минут не меняется.
- Видеовкладка получает сигналы изменения presence и stream через защищённый BFF WebSocket; после сигнала перечитывает актуальный REST status и восстанавливается после разрыва соединения.
- Суточный usage может проводиться после локальной полуночи отдельным фоновым worker; он выключен по умолчанию и требует явного списка tenant.

### Changed

- Список L4Desk-терминалов использует всю доступную ширину окна; столбцы и действия стали компактнее, поэтому на обычном десктопе горизонтальная прокрутка не нужна.
- Страница видеонаблюдения при открытии сворачивает боковую навигацию, отдаёт больше места кадру и размещает действия трансляции и управления рядом с ним. Режимы в интерфейсе называются Medium и HD; браузер позволяет выбрать подгонку кадра или просмотр в исходном размере.
- Периодический опрос состояния app1 заменён watch-сигналами; счётчик кадров берётся из локальной статистики WebRTC без HTTP-опроса. Продление аренды сохранено.
- Владелец L4Desk может получить аренду video/input/console только для устройства своего tenant; console WebSocket требует явную аренду.

### Fixed

- Первое включение управления после запуска видео больше не зависает при отказе аренды: интерфейс показывает причину и позволяет повторить попытку. Управление рабочим столом доступно при профилях Medium и HD; при его отключении трансляция продолжает работать. Запрет для камеры и проверки аренды сохранены.
- Читающие инструменты L4mcp объявлены безопасными для просмотра; инструкция Codex устанавливает режим `writes`, чтобы список и состояние терминалов, проверка консоли и отчёты не требовали подтверждения. Выдача и отзыв PIN, а также выполнение команды сохраняют отдельный контроль.
- Страница MCP снова показывает карточки будущих сценариев и принимает пожелания через существующую форму обратной связи рядом с рабочими настройками подключения.
- Публичный маршрут L4mcp пропускает клиентов без браузерной cookie к проверке API-токена в MenuBuilder; страница подключения поясняет назначение `bearer_token_env_var`.

- Клавиша удалённого управления передаёт печатный символ только при нажатии; событие отпускания освобождает VK без повторной вставки символа.

- Владелец L4Desk с ролью 5 может открыть профиль в настройках; ограничение доступа наблюдателя сохранено.

- При открытии видео по номеру терминала источники загружаются автоматически; запоздалый inventory предыдущего устройства не заменяет текущий.

- Мягко удалённые L4Desk-терминалы исключаются из списка и счётчика страниц; обычные терминалы без L4Desk-записи остаются видимыми.

- Статус L4Desk-терминалов обновляется по тому же источнику IoT, что управление устройствами. Недоступный статус отображается как неизвестный; PIN и устаревшие ответы не переносятся между tenant.
- Мастер больше не предлагает устаревший агент 1.7.7. Принята версия 1.8.2-beta-1; до публикации подтверждённой ссылки загрузка не предлагается.

- В узком окне таблицы терминалов и лицензий сохраняют читаемую ширину и прокручиваются горизонтально. Основной идентификатор — номер терминала; SN сокращается в одну строку с просмотром и копированием полного значения.

- Успешный платёж и повторный poll обновляют сохранённое коммерческое состояние tenant в той же транзакции; после погашения долга Hub показывает восстановленный доступ без ожидания фонового worker. Частичная оплата не снимает блокировку при оставшемся долге после grace.
- Административный Hub на основном сайте направляется в MenuBuilder с проверенным JWT; финансовый обзор корректно показывает баланс, когда PostgreSQL возвращает сумму в типе Decimal.
- WebSocket просмотра видео допускает владельца L4Desk с ролью 5 без отдельного `video:view` в JWT, сохраняя проверку прав viewer и принадлежности устройства tenant.
- Владелец L4Desk с ролью 5 получает во фронтенде то же право просмотра видео, что и в backend; состояние `control/status` и обновления видеовкладки загружаются при выборе терминала.
- Compose передаёт значение `AUTH_USERS` из приватного env-файла буквально: символы `$` в хеше больше не воспринимаются как переменные окружения и не повреждают резервную авторизацию.
- Регистрация и создание организации администратором резервируют `org_id` в IoT перед записью tenant; занятый ID больше не назначается другой организации. Повтор подтверждения регистрации использует прежнюю резервацию, а недоступный IoT останавливает создание tenant.
- Video/console usage фиксируется подтверждёнными порциями примерно раз в минуту и остатком при штатной остановке. Курсор и суточный счётчик обновляются одной транзакцией; недоказанный хвост после потери provider epoch не начисляется. Длинная сессия больше не объединяет раздельные запуски после сбоя.
- Поздние порции после проведения суток накапливаются в audit, включая порции без денежного изменения; следующая финансовая корректировка рассчитывается от накопленного итога, сохраняя исходную проведённую строку.
- Кратковременный сброс нового соединения PostgreSQL повторяется до пяти раз с паузой; соединение внутри начатой транзакции не переподключается автоматически.
- Проверка бесплатного суточного лимита использует локальную дату tenant, совпадающую с учётом минут, в том числе до первого платежа.
- Продление video lease теперь продлевает watchdog соответствующей медиасессии ingress; активная трансляция не теряет RTP-маршрут после 600 секунд.
- Штатная остановка трансляции удаляет активную медиасессию ingress по SN, даже если ID потока отличается от ID медиасессии.
- Onboarding передаёт платформе уже выданный `device_id` и подтверждает совпадение tenant, terminal, SN и ID перед статусом ready. Успешный provisioning отражается в runtime-записи терминала.
- Локальные video/console сессии сохраняются и закрываются по внутреннему ID терминала; закрытый интервал единожды попадает в суточный usage. Месячное начисление обрабатывает только подтверждённый IoT `device_online` для явно включённых tenant.
- Аренда браузера использует session ID из JWT: несовпадающий `session_id` в acquire отклоняется, а ошибка транспорта при release больше не выдаётся за успешное освобождение.
- Редактирование тестового владельца L4Desk в админке сохраняет `role_id=5`; backend отклоняет несовпадение текстовой роли и её ID, чтобы смена пароля не лишала пользователя доступа к консоли.
- Повторное подключение консоли создаёт локальную сессию с уникальным ID аренды; прежнее повторное использование browser session ID приводило к конфликту уникальности и HTTP 500.

## 2026-09-22

### Added

- Корневой раздел L4Desk «Терминалы» (`/terminals`): список, readiness, read-only SN/`device_id`, «Подключить терминал», повтор provisioning, переходы в консоль и видеонаблюдение.
- Единый server-side use case создания terminal business record (`terminal_creation_service`) с канонической формулой SN `a4b<device_id>c<random>d<DDMMYY>`.

### Changed

- Порядок корневых разделов L4Desk: Терминалы → Видеонаблюдение → Консоль → Настройки → MCP → Лицензии. Classic profile не изменён.
- Мастер подключения перенесён из «Консоли» в «Терминалы»; консоль без терминалов направляет в «Терминалы».
- Новые `device_id` выдаются только в диапазоне `1000001…1999999` (admin и L4Desk).
- Форма создания терминала больше не принимает SN и `device_id` от пользователя.

### Removed

- Отдельная формула SN `SN-L4D-…` и allocator `max(device_id)+1` в L4Desk onboarding.
- Вложенный раздел «Терминалы» в L4Desk-настройках (URL `/settings/terminals` в L4Desk redirect на `/terminals`).
- Действие создания терминала из «Консоли».

### Fixed

- Provisioning больше не переписывает уже выданные SN и `device_id`.
- Повтор идемпотентной L4Desk-операции не создаёт второй terminal business record.

## 2026-08-31

### Added

- Появился tenant-aware каталог категорий и услуг с отдельным API и экраном управления; сервисы меню связываются с элементами каталога.
- Версии меню и их снимки распространяются до терминальных привязок, поэтому опубликованное состояние можно однозначно сопоставить с терминалом.
- Мониторинг использует детерминированный gauge-движок и RabbitMQ/MQTT-шину; отображаются согласованные агрегаты и статусы.
- Раздел интеграций стал полноценным каталогом доступных подключений, а отчёты получили явные фильтры периода.
- В карточке устройства доступны обнаружение коллизий идентификаторов и операции управления клонами.

### Changed

- Интеграция с Leo4 IoT использует `internal API v1`; nginx передаёт нормализованный tenant/user context и внутренний service key вместо пользовательского JWT.
- Переключение tenant-контекста обновляет пользовательскую сессию и связанные кэши интерфейса, поэтому данные экранов соответствуют выбранной организации.
- Биллинг рассчитывает статус по активности терминала и сроку лицензии; продление и восстановление доступа представлены как разные режимы оплаты.
- Административный список терминалов показывает актуальный IoT-статус и использует унифицированную модель активности.
- Фильтрация привязок меню ограничена выбранным tenant-контекстом и не смешивает терминалы организаций.

### Removed

- UI и billing API больше не зависят от `licenses.is_active`, `licenses.renewal_enabled` и `licenses.deactivation_requested_at`.
- Интеграция с IoT-платформой больше не использует прежние внешние маршруты вместо внутреннего API-контракта.

### Fixed

- Исправлена tenant-фильтрация terminal bindings.
- Согласованы расчёты billing summary, статусов, задолженности и прогнозов после перехода на единый признак активности терминала.
- Мониторинг и отчёты сохраняют выбранный tenant и временной диапазон при повторных запросах.
