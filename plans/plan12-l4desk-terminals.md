# План 12: терминалы L4Desk и инвентаризация L4 Tools

Статус: реализация и локальная проверка завершены; выпуск выполняется по базовым
веткам main (etranprocessing) и master (IoT), через выделенный билдер.
Основание: запрос пользователя на реализацию, push и deploy, включая уточнения
о FM, неагрессивном отключении и независимой доставке события 75.

## Согласованный результат

- Адаптивный список терминалов с серверными поиском, фильтрацией и пагинацией.
  Presence поступает через текущий batch API IoT, с tenant-кешем и single flight.
- Иконки консоли, экрана, FM и сводки. FM открывает выбранный терминал по device_id;
  пользователь самостоятельно запускает подключение. Сводка переиспользует паспорт
  и теги Classic, без команд и журнала событий.
- Версия установленного комплекта показывается в строке; время публикации события
  и признак давности — в подсказке. Неизвестная версия остаётся неизвестной.
- Названия разделов: «Экран терминала» и «IP-камеры».
- Пользовательское отключение L4Desk запрещает будущие использования, включая policy
  MQTT/RTP/FM. Административный is_active, оплата, free ordinal и enrollment сохраняются.
  Текущие сессии не разыскиваются, клиент RabbitMQ не удаляется, force stop не отправляется.
- Сертификат: отдельный выбор автоматического RPC 7011 или ручного setup PIN.
  Повторы сохраняют operation identity. Одновременное выполнение способов не объявляется
  безопасным; UI предупреждает о конкуренции. Capability не выводится из версии EXE.

## Владельцы и контракт

Канонический контракт: [инвентаризация терминала](../docs/etran_arch-terminal-inventory.md).
Raw событие 75 предоставлено пользователем отдельно. IoT владеет приёмом события,
trusted binding и durable outbox; MenuBuilder — валидацией, inbox и текущей проекцией;
shared содержит декларативные модели, ProcessingBackend владеет миграцией 033.

Allowlist внутренней доставки — строго {75}. Отдельный ключ и worker не изменяют
публичные API-webhooks, их подписки, ответы, авторизацию и retry state. В browser
нет внутреннего ключа. Список читает локальную PostgreSQL-проекцию без polling
истории события 75. Начальное заполнение — однократный batch replay из БД IoT.
UUID является identity события; 101 не монотонен и может иметь коллизии.
445 — установленный полный комплект, 444 — наблюдаемые компоненты, 102 — публикация.
Наблюдения сертификата никогда не перезаписывают terminals.cert_serial.

## Реализованные этапы

1. Nullable user_disabled_at, projection и inbox; аддитивная миграция 033.
2. Отдельная tenant-scoped операция отключения и admission/policy deny;
   фоновые stop-механизмы сохраняют коммерческие и административные причины.
3. Агрегированный серверный список, batch presence, bounded cache, UI и FM navigation.
4. Защищённый скрытый ingress; валидация, транзакционная запись, UUID/hash idempotency,
   защита от старых событий, ограничение тела до JSON parser.
5. IoT outbox, отдельный HTTP worker, backoff, identity recheck, startup replay,
   retention и независимость legacy event-number dedup от UUID inventory.
6. Локальные тесты backend/shared/IoT, frontend build и браузерные проверки.

## Порядок выпуска и проверки

1. Выпустить совместимость MenuBuilder 032/033 до изменения схемы — выполнено:
   main e043c06f42dc064664aed400d98a8532edf7d354, сборка и деплой через билдер.
2. Проверить сканирование секретов и отправить основную реализацию в базовые ветки.
3. Настроить отдельный ключ в приватных runtime env двух сервисов штатным
   deploy/configure_inventory_delivery.py; значения не выводить и не коммитить.
4. Через билдер выпустить ProcessingBackend, применить 033, затем MenuBuilder backend
   и frontend. Выпустить app1 из принятого master по immutable registry digest.
5. Проверить revision/image/health, версии обеих схем, конфигурацию private delivery,
   реальные outcomes регистра и неизменность контейнеров инфраструктуры.
6. Зафиксировать handoff с SHA, digest и выполненными проверками; удалить временные
   файлы текущей задачи. Физические терминальные команды не подменять mock evidence.

Подробные результаты проверок и выпуска принадлежат handoff задачи; этот план
не является доказательством выполнения команды на физическом терминале.
