# Пользовательские события l4con из удаленной консоли

Контракт l4con 1.9.3. Изменения относятся к l4con и документации;
ProcessingBackend, MenuBuilder, l4mcp и другие инструменты не меняются.

## Запуск

Команда работает только внутри удаленной команды `7001`, запущенной через
этот же работающий l4con, и в ее дочерних процессах. Ее можно вызывать из
веб-консоли или через существующий `console_run` l4mcp. Обычный запуск из
локальной консоли, даже под той же учетной записью, не разрешает отправку.

```text
l4con --send-event -event-code=999 -event-payload="some text" -event-exit-code=0 -event-correlation-id=12345678-1234-1234-1234-123456789abc
```

CLI не повышает права, не обращается к SCM и не открывает MQTT-соединение.
Он выполняется под учетной записью вызывающего процесса. В текущем
исполнителе удаленный cmd/PowerShell наследует учетную запись службы l4con;
это не переключение на пользователя браузера или интерактивного рабочего стола.
Запуск тихий: stdout/stderr CLI пусты, результат возвращается кодом завершения.
Обычный вывод удаленной консоли (prompt команды и EOF) сохраняется.

## Аргументы и данные события

| Аргумент | Тег | Правило |
|---|---|---|
| `-event-code` | `200` | Число 900–999; без аргумента 999; неверное значение отклоняет вызов |
| `-event-payload` | `300[0]["446"]` | Строка; JSON внутри не разбирается и не нормализуется. При отсутствии аргумента тег отсутствует; пустой аргумент дает пустую строку |
| `-event-exit-code` | `300[0]["447"]` | JSON-число int32; по умолчанию 0; неверное значение/переполнение дает −1 |
| `-event-correlation-id` | `300[0]["448"]` | Опциональная строка UUID формата `8-4-4-4-12` hex, регистр сохраняется. Если аргумент отсутствует, тег отсутствует. Указанное пустое/неверное значение отклоняет вызов целиком |

Payload ограничен **1024 байтами UTF-8 до JSON-экранирования**, а не числом
символов. При превышении событие отправляется без `446`, а `447` становится
**−2**, даже если пользователь указал другой exit-code. Остальные поля,
включая валидный `448`, сохраняются. Строка, JSON-текст и уже
стрингифицированный JSON передаются буквально и экранируются один раз для
внешнего события. Дубли аргументов и неизвестные аргументы отклоняются.

```json
{
  "101": 123456,
  "102": "2026-10-01T12:00:00Z",
  "200": 999,
  "300": [{
    "324": "<SN>",
    "440": "l4con",
    "446": "{\"result\":\"ok\"}",
    "447": 0,
    "448": "12345678-1234-1234-1234-123456789abc"
  }],
  "correlationData": "<generated event UUID>"
}
```

`448` — внешний идентификатор вызывающей системы; он не заменяет генерируемый
UUID `correlationData` события или идентификаторы console task/session.
Теги `446–448` продолжают диапазон `440–445`, используемый в
[событии 75](term_tool-event75-inventory.md).

## Примеры для пользователя консоли

В cmd текст JSON передается как один аргумент с экранированными кавычками:

```bat
l4con --send-event -event-code=999 -event-payload="{\"result\":\"ok\"}" -event-exit-code=0
echo %ERRORLEVEL%
```

Для Windows PowerShell 5.1, используемого штатным исполнителем, удобен
stop-parsing token для статических аргументов native exe:

```powershell
l4con --% --send-event -event-code=999 -event-payload="{\"result\":\"ok\"}" -event-exit-code=0
$LASTEXITCODE
```

`--%` — синтаксис PowerShell, он не передается l4con. Он не позволяет обычную
подстановку PowerShell-переменных справа; при динамических аргументах нужно
учесть правила передачи argv конкретной версии PowerShell. Для простого
текста достаточно `l4con --send-event -event-payload="operation finished"`.

Сам исполнитель l4con передает исходный PowerShell-текст через штатный
`-EncodedCommand` (UTF-16LE/base64), сохраняя кавычки и выражения. Это исправляет
обнаруженную при реальной проверке потерю кавычек в прежнем `-Command` launch.
Это кодирование команды для запуска, а не шифрование данных.

## Использование из l4mcp

Сначала `console_preflight(device_id=<точный ID>)`, затем штатный
`console_run` с тем же ID. Нового MCP-инструмента или endpoint нет:

```json
{
  "device_id": 773,
  "shell": "cmd",
  "timeout_sec": 10,
  "command": "l4con --send-event -event-code=999 -event-payload=\"{\\\"result\\\":\\\"ok\\\"}\" -event-correlation-id=12345678-1234-1234-1234-123456789abc"
}
```

Это пример явной отправки пользовательского события, а не read-only
диагностика. Сохраняются действующие tenant/access checks, console lease,
учет использования и освобождение аренды. Проверять нужно `exit_code` в
результате `console_run`, а не только `status=completed`. Для cmd при
добавлении дальнейших команд необходимо сохранить код возврата l4con:
обычные последующие команды могут его перезаписать.

## Ответ CLI и доставка

| Код завершения CLI | Значение |
|---|---|
| `0` | Работающий l4con передал MQTT PUBLISH в свое установленное соединение |
| `2` | Неверные аргументы, event-code или указанный внешний UUID |
| `3` | Отправитель не принадлежит разрешенной выполняющейся команде либо доступ уже закрыт |
| `4` | IPC недоступен/занят либо истек таймаут взаимодействия |
| `5` | Превышен общий лимит пользовательских событий |
| `6` | MQTT-соединение службы не готово либо публикация не удалась |

CLI-код и тег `447` независимы. Например, событие с `447=-2` может успешно
отправиться с CLI-кодом 0. Успех CLI не подтверждает запись на сервере:
он не ожидает прикладного ACK или PUBACK. При разрыве соединения/таймауте
доставка может быть неопределенной; автоматических повторов нет.
При запрещенном внешнем MQTT в leo4proxy локальный Mosquitto может принять
сообщение, но доставка серверу зависит от его моста.

## Доступ, ограничение потока и жизненный цикл

Локальный named pipe `L4Con_UserEvents_v1` отклоняет удаленных клиентов.
ACL допускает SYSTEM, администраторов и интерактивных пользователей к IPC,
но разрешение на публикацию определяется службой по PID отправителя из
Windows и `IsProcessInJob`. Переданный клиентом PID/session_id не используется.
Job не разрешает breakaway, его handle не наследуется.

Корневой cmd/PowerShell создается suspended, включается в Job и только затем
запускается. Разрешение действует пока выполняются команда и ее дочерние
процессы, в пределах TTL. Если корневой shell завершился раньше потомков,
исполнитель ожидает их завершения с тем же TTL. Отмена, TTL, output limit и
завершение службы закрывают разрешение и завершают принадлежащие команде
процессы. При невозможности назначить Job (в том числе ограничения вложенных
Jobs на Windows 7) команда может выполняться, но пользовательские события
для нее запрещены. Это не защита от администратора/SYSTEM.

Для всех разрешенных отправителей действует **одна попытка публикации за
1000 мс**, без всплеска, очереди и автоповторов. Событие 75 и presence этим
лимитом не ограничиваются. Один IPC-обработчик обслуживает один запрос;
занятый endpoint дает немедленный отказ. Чтение запроса ограничено одной
секундой. Отказы не пишутся в лог. Используются bounded buffers и повторная
валидация на стороне службы. Проверка доступа и публикация сериализованы
с отзывом Job-разрешения; повторное исполнение не использует старый контекст.
