# Архитектура и оптимизация MenuBuilder/Frontend

## 1. Обзор и технологический стек

**MenuBuilder/Frontend** — одностраничное веб-приложение (SPA), предоставляющее веб-интерфейс администраторам тенантов и суперадминистраторам платформы **etranprocessing**. Приложение обеспечивает управление меню платежных терминалов, мониторинг их состояния в реальном времени, финансовую и транзакционную отчетность, а также управление лицензиями терминалов и выпуском PIN-кодов mTLS-сертификатов.

### Технологический стек:
* **UI-фреймворк:** `React 19.1.0` + `React DOM 19.1.0`
* **UI-компоненты:** `Ant Design 6.6.1` (`antd`) + `@ant-design/icons 6.3.2`
* **Маршрутизация:** `React Router 7.6.0` (`react-router`)
* **Сетевой слой:** `Axios 1.9.0` (с типизированными клиентами и интерцепторами)
* **Язык:** `TypeScript 5.8.2` (строгая типизация)
* **Сборщик и Dev-сервер:** `Vite 6.3.0` (`@vitejs/plugin-react 4.5.0`)
* **Дизайн-система:** Ant Design Design Tokens (`src/theme.ts`) + модульные и глобальные CSS-правила (`src/styles/global.css`)

## 2. Архитектура бандла и Code Splitting

До оптимизации бандл собирался единым монолитным JS-файлом размером **1 517.60 КБ** (gzip: 478.71 КБ), что замедляло первичную загрузку приложения.

### 2.1. Динамический импорт маршрутов (Lazy Loading)
В `src/App.tsx` все основные экраны переведены на асинхронную загрузку с использованием `React.lazy()` и компонента-заглушки `<Suspense fallback={<LoadingFallback />}>`:

```tsx
const AppLayout = lazy(() => import("./routes/layout"));
const LoginPage = lazy(() => import("./routes/login"));
const MonitoringPage = lazy(() => import("./routes/monitoring"));
const ReportsPage = lazy(() => import("./routes/reports"));
const BillingPage = lazy(() => import("./routes/billing"));
const VariantsPage = lazy(() => import("./routes/variants"));
const AdminOrganizationsPage = lazy(() => import("./routes/admin-organizations"));
const AdminTerminalsPage = lazy(() => import("./routes/admin-terminals"));
```

### 2.2. Стратегия разделения вендоров (Rollup Manual Chunks)
В `vite.config.ts` настроена гранулярная изоляция крупных библиотек в независимые кэшируемые чанки:

```typescript
build: {
  rollupOptions: {
    output: {
      manualChunks: {
        "vendor-react": ["react", "react-dom", "react-router"],
        "vendor-antd": ["antd", "@ant-design/icons"],
        "vendor-axios": ["axios"],
      },
    },
  },
}
```

### 2.3. Результаты оптимизации бандла
* Размер корневого чанка приложения сокращен с **1 517.60 КБ** до **16.12 КБ** (уменьшение более чем в 90 раз).
* Библиотеки Ant Design и React изолированы в отдельные вендор-чанки, которые кэшируются браузером клиента и не перезагружаются при обновлениях страниц приложения.
* Неиспользуемые legacy-файлы (`dashboard.tsx`, `groups.tsx`, `services.tsx`) удалены из репозитория.

## 3. Макет (Layout) и навигация

Для предотвращения потери контекста при прокрутке больших объемов табличных данных реализована концепция фиксированной навигации:

1. **Главный Layout (`src/routes/layout.tsx`):**
   * Боковой сайдбар (`Sider`) зафиксирован через `position: sticky; top: 0; height: 100vh; overflow-y: auto`.
   * Шапка приложения (`Header`) содержит переключатель организации (`OrgSwitcher`) и профиль пользователя.
2. **Вложенные боковые панели (`src/components/SectionLayout.tsx`, `src/routes/reports.tsx`):**
   * Боковые меню разделов «Отчеты», «Администрирование», «Интеграции» и «Управление меню» зафиксированы (`position: sticky; top: 64px; max-height: calc(100vh - 80px); overflow-y: auto`).
   * При прокрутке правого контентного блока с таблицами меню навигации всегда остается в поле зрения пользователя.

## 4. UI/UX стандарты и система дизайн-токенов

### 4.1. Централизованная тема (`src/theme.ts`)
Дизайн-токены Ant Design v6 централизованно настроены для обеспечения высокой плотности информации (data-dense UI):
* Таблицы (`Table`): компактные отступы ячеек (`cellPaddingBlockSM: 4`, `cellPaddingInlineSM: 8`), скругление заголовков `headerBorderRadius: 10`, фон шапки `#fafbfc`.
* Выпадающие списки (`Select`, `Dropdown`, `DatePicker`):
  * Размер шрифта увеличен до `13px` с комфортной высотой строк (`optionPadding: "7px 12px"`).
  * Выделенный пункт подсвечивается мягким фоном `#eff4ff` и акцентным цветом `#2563eb`.
  * Для всех селекторов и их элементов гарантирован курсор-указатель (`cursor: pointer`).

### 4.2. Плотность отображения и пагинация
* **Таблицы мониторинга и отчетов (`src/styles/global.css`):**
  * Класс `.compact-table`: вертикальные отступы `3px 6px`, уменьшенная высота строк.
  * Класс `.reports-table`: отступы `4px 8px` для финансовых таблиц.
* **Стандарт пагинации:** Дефолтное количество записей на страницу для всех таблиц приложения установлено в **50** (вместо 10 или 100), обеспечивая баланс между удобством анализа и нагрузкой на сеть.

## 5. Доменные экраны и функциональность

### 5.1. Мониторинг терминалов (`src/routes/monitoring.tsx`)
* Отображение оперативного состояния терминалов: балансы, купюроприемники, время последней активности, версии ПО.
* Применение стиля `.compact-table` для максимальной вместимости строк на экране.
* В колонке «Тип терминала» и карточках детального просмотра к названию типа добавлен числовой идентификатор: `{ID}: {Название}` (например, `1: Standard Kiosk`).

### 5.2. Отчеты (`src/routes/reports.tsx`)
1. **Отчет «По терминалам»:**
   * Убраны избыточные колонки `SN` и `TSP (кол-во)`, удален фильтр по коду ТСП.
   * Установлен порядок колонок: **Терминал**, **Сумма** (руб.), **Платежей** (кол-во).
   * Ширина колонок оптимизирована, таблица не растягивается избыточно на сверхшироких экранах.
2. **Отчет «По ТСП»:**
   * Автоматически сопоставляет код ТСП с актуальным наименованием услуги из связанного меню через `getServices()`. При отсутствии услуги выводится текстовый мнемокод/название.
   * Порядок колонок: **ТСП код**, **Название**, **Сумма**, **Платежей**, **Терминалов**.
3. **Отчет «Платежи»:**
   * В колонке «ТСП» отображается составное наименование в формате `{Код ТСП}: {Наименование}`.
4. **Отчет «Инкассация»:**
   * Журнал инкассаций терминалов с фильтрацией по датам и номерам устройств, пагинация 50 строк.

### 5.3. Биллинг и лицензирование (`src/routes/billing.tsx`)
* **Прогноз по периодам:** Карточки прогноза задолженности и продления переведены на адаптивный CSS Grid `grid-template-columns: repeat(auto-fit, minmax(160px, 1fr))`, что предотвращает нежелательный перенос карточек на мониторах с разрешением 1920px.
* **Корзина и оформление (`CheckoutModal.tsx`):** Пакетный выбор терминалов, поддержка режимов `standard`, `post_factum` и `cert_linked`, калькуляция авансовых периодов.
* **Заказ сертификатов (`CertificatePinModal.tsx`):** Генерация PIN-кодов для выпуска/продления клиентских mTLS-сертификатов терминалов.

### 5.4. Администрирование (`src/routes/admin-terminals.tsx`, `src/routes/admin-organizations.tsx`)
* **Терминалы (`admin-terminals.tsx`):**
  * Введен обязательный фильтр по выбранной организации: в списке всегда отображаются только терминалы текущей организации.
  * Устранена избыточная кнопка «Обновить» (данные автоматически перезагружаются при смене организации или параметров).
  * Типы терминалов выводятся с ID: `{ID}: {Название}`.
* **Организации (`admin-organizations.tsx`):**
  * Управление контактами (`email`, `phone`, `notify_by_email`), тарифными планами, минимальными и разрешенными периодами продления (`allowed_billing_periods`).

### 5.5. Конструктор меню (`src/routes/variants.tsx`, `src/routes/terminals.tsx`)
* Трехпанельная организация интерфейса: варианты меню -> иерархическое дерево категорий (`Tree`) -> таблица услуг (`Table`).
* Назначение вариантов меню на конкретные терминалы организации (`TerminalMenuBinding`).

## 6. Мультитенантность и безопасность

1. **JWT-аутентификация:**
   * Токен хранится в `localStorage` под ключом `mb_token`.
   * Сетевой клиент `src/api/client.ts` автоматически внедряет заголовок `Authorization: Bearer <token>` во все исходящие запросы.
   * При получении ответа `401 Unauthorized` интерцептор очищает локальное хранилище и перенаправляет пользователя на `/login`.
2. **Переключение тенантов (`OrgSwitcher`):**
   * Для суперадминистраторов компонент `OrgSwitcher` позволяет мгновенно сменить рабочий контекст организации через эндпоинт `POST /api/admin/switch-tenant`.
   * Полученный тенант-токен сохраняется, интерфейс изолирует данные выбранного тенанта.

## 7. Сборка и регламент развертывания

### 7.1. Локальная проверка и сборка
```bash
cd MenuBuilder/frontend
npm run build
```
Скрипт `npm run build` выполняет проверку типов TypeScript (`tsc -b`) и компиляцию продакшн-бандла в директорию `dist/`.

### 7.2. Развертывание в Docker (Production)
* Контейнер `menubuilder-frontend` в `docker-compose.yaml` использует live-mount каталога `./MenuBuilder/frontend/dist/` в директорию Nginx `/usr/share/nginx/html`.
* После выполнения `npm run build` обновленные файлы статики немедленно отдаются Nginx без необходимости перезапуска контейнера. Перезапуск контейнера требуется только при изменении конфигурации `nginx.conf`.
