# Подписки L4Desk: правила и переход

Дата: 2026-10-03. Реализация `8bb0359` выпущена в production через builder/registry/pull; схема 029, YooKassa OFF. [Результат релиза](../.agent-context/tasks/completed/2026-10-03-l4desk-terminal-subscriptions-release.md).

## Что видит пользователь

Первый неудалённый терминал по неизменяемому порядковому номеру бесплатен без лимита времени. Можно подготовить второй терминал. Создание третьего и следующих разрешается, когда есть хотя бы один дополнительный терминал с действующей оплаченной подпиской; grace для этого не подходит. Административно выключенный или удалённый терминал не получает доступ от оплаты.

При `YOOKASSA_ENABLED=false` бесплатный терминал работает, дополнительные подготовлены, но их платные возможности недоступны. Покупки запрещены сервером. Включение того же флага в обоих backend открывает покупку и доступ по уже сохранённым срокам. Новые сроки само включение флага не выдаёт. Настройки читаются при запуске процессов, поэтому изменение окружения требует штатного обновления контейнеров.

Подписка приобретается отдельно для выбранных терминалов на 1, 3, 6 или 12 календарных месяцев. Цена задаётся `SUBSCRIPTION_MONTH_PRICE_KOPECKS` (по умолчанию 10000, то есть 100 ₽ за месяц). Продление идёт от большей из дат: подтверждённая дата оплаты или текущий `paid_until`. Расчёт выполняется в часовом поясе tenant с ограничением дня последним днём целевого месяца. После истечения оплаченного срока предоставляются три календарных дня grace. У никогда не оплаченного терминала grace отсутствует. Границы периода сохраняются в аудите, последующая смена часового пояса не меняет выданный grace.

Страница «Подписки» показывает состояние каждого терминала, срок, grace, причину ограничения и следующее действие. Корзина показывает выбранные терминалы, месяцы и серверную сумму до перехода к оплате; история позволяет продолжить или проверить платёж. Отдельная статистика времени console/video показывает нагрузку за 7/30/90 дней и по терминалам. В списке терминалов доступны те же статусы и объяснение ограничения создания. Суперпользователь корректирует точный срок с обязательной причиной и аудитом, без отмены административного выключения.

## Владение и контракты

| Компонент | Ответственность |
|---|---|
| shared | Декларативный `L4DeskTerminal.paid_until`, контракт схемы 029 |
| ProcessingBackend | Миграция 029; вычисляемая transport policy для MQTT/RTP |
| MenuBuilder backend | `/api/subscriptions`, корзина, подтверждение провайдера, admission/stop, статистика, уведомления |
| MenuBuilder frontend | Объяснение состояния, выбор периода, оплата, история, нагрузка, административная корректировка |

API также доступен через `/api/v1/subscriptions`. Frontend использует `/api/subscriptions`, чтобы не зависеть от внешней маршрутизации `/api/v1` в app1. Webhook сохраняет прежний путь `/api/v1/finance/yookassa/webhook` и `/api/finance/yookassa/webhook`, но обрабатывает только новые заказы с назначением подписки. Подтверждение всегда перечитывает платёж у провайдера и сверяет ID, RUB, сумму, tenant, назначение, хеш корзины и дату capture.

Заказ использует существующие `FinPayment` и `L4DeskAuditEvent`. Снимок содержит состав корзины, цену, часовой пояс и тело запроса провайдеру с чеком. Повтор после timeout использует ту же операцию и снимок. Блокировка tenant и платежа сериализует выдачу сроков; повторный webhook или параллельная проверка не продлевает их второй раз. Незавершённый заказ запрещает удаление терминалов tenant, чтобы не изменить назначение бесплатного терминала и оплачиваемых позиций в процессе оплаты. Удаление после завершения заказов переносит бесплатный статус на следующий неудалённый порядковый номер, но не включает терминал административно.

## Что заморожено и что сохранено

Баланс, почасовая цена, бесплатные минуты, месячные начисления по presence, posting usage, tenant-wide entitlement/grace и старые финансовые workers исключены из активного пути. Старые таблицы, ограничения и сервисы расчётов сохранены как архив совместимости; их наличие не означает работающий биллинг. Старые финансовые mutation API возвращают 410 либо отсутствуют. Admin Hub сохраняет чтение прежних финансов и убирает начисления, сторно и reconciliation. Подписочные заказы исключены из архивной истории платежей и её предупреждений об отсутствии старых ledger-проводок.

Технические сессии, epoch, cursor, stop outbox и расчёт длительности продолжают работать. Новый `UsageService` использует дневную таблицу как адаптер старой схемы, создавая новые строки с нулевыми денежными полями. Поле `free_seconds` в новых строках является техническим адаптером ограничения суммы секунд, а не бесплатной квотой. Уже проведённые строки не переписываются: поздняя длительность сохраняется аудитом и объединяется при чтении статистики. Существующие неопубликованные денежные значения также не пересчитываются. Presence больше не порождает начисления.

Session worker действует адресно по терминалу и перепроверяет право перед retry. Старый `entitlement_blocked` запрос отменяется, если текущая подписка разрешает сессию. Техническая остановка и подтверждённый хвост времени сохраняются независимо от денег. Classic без L4Desk tenant profile не включается в эту модель автоматически.

Уведомления 7/3/1 день, grace и окончание используют аудит как outbox. Отправка имеет ограниченные повторы и восстановление зависшего claim. Доставка email best effort: сбой между отправкой письма и фиксацией результата может дать повторное письмо; на сроки подписки это не влияет. Worker обходит незавершённые заказы порциями с продвижением курсора, включая при ошибках провайдера.

## Единственная миграция

`ProcessingBackend/backend/alembic/versions/029_terminal_subscription.py` добавляет nullable timestamptz `paid_until` к `l4desk_terminals`. Причина: среди прежних полей нет безопасного поля для срока конкретного терминала; даты технических событий, сертификатов и tenant cycle имеют другое назначение. Новых таблиц, drop и конвертации старых денег нет. Существующие дополнительные терминалы начинают с NULL: старый баланс не считается оплатой новой подписки.

MenuBuilder проверяет revision 029 и наличие колонки при старте. Обновить только один consumer shared нельзя. Обратная миграция намеренно запрещена, чтобы не потерять оплаченные права; rollback выполняется совместимым с 029 образом без запуска прежних денежных workers.

## Порядок применения релиза

1. По стандартному release flow собрать образы из одной ревизии, проверить shared provenance и конфигурацию обоих backend. До перехода оставить YooKassa выключенной.
2. Остановить прежние финансовые workers/старый MenuBuilder; применить `alembic upgrade head` образом ProcessingBackend. Не конвертировать деньги и не импортировать данные автоматически.
3. Обновить ProcessingBackend и MenuBuilder на согласованные образы; выпустить frontend. Проверить schema readiness, бесплатный терминал, запрет дополнительных при выключенных оплатах, остановку адресных сессий и статистику без проводок. Учесть старые явные `L4DESK_REGISTRATION_ENABLED` / onboarding значения окружения, которые переопределяют новые defaults.
4. Для коммерческого включения настроить ключи магазина, HTTPS return URL и чек через окружение; включить `YOOKASSA_ENABLED` в обоих backend. Старые `l4desk_billing_*` flags не должны запускать архивную модель. Проверить отдельным разрешённым тестовым платежом весь provider flow и фактические MQTT/RTP решения.

Production-релиз применён, но настоящий платёж и hardware E2E не выполнялись.
