# L4mcp v1: консоль, сертификаты и доступ

## Владение и подключение

`MenuBuilder/l4mcp` — MCP HTTP service. Публичный путь `/api/mcp/proxy` проходит через MenuBuilder backend; API-токен выпускает и отзывает тот же backend. Роли 1, 3 и 5 получают право по роли, без отдельного разрешения суперпользователя. При выпуске токена нужен выбранный tenant. Для ролей 3 и 5 tenant берётся из актуальной записи пользователя; роль 1 фиксирует выбранный tenant в подписанном токене. Отзыв и смена роли проверяются на каждом запросе.

На странице «MCP» пользователь выпускает токен и видит настройки Codex и Claude Code. Токен показывается однократно. Его не следует помещать в репозиторий или диалог с агентом.

## Консоль

1. Агент спрашивает у пользователя точный `device_id`. Без него `console_preflight` и `console_run` возвращают `device_id_required` без сетевого запроса.
2. MenuBuilder сверяет принадлежность терминала и по **одному** устройству запрашивает IoT. Нужны `sys=windows`, `last_checked_result=true`, отсутствие блокировки и `svc_connect=true` (`l4con`); иначе MCP возвращает причину и не создаёт аренду/задачу.
3. `console_run` повторяет проверку непосредственно перед командой, получает штатную аренду `scope=console`, подключается к штатному diagnostics WebSocket с этим `lease_id` и отправляет `exec` (RPC 7001). По завершении, тайм-ауту или ошибке WebSocket закрывается, аренда освобождается через MenuBuilder. Учёт остаётся в существующем механизме console usage.
4. V1 выполняет одну короткую команду на вызов: до 20 секунд и 32 КиБ вывода. Для длинного вывода и продолжения по курсору потребуется отдельный V2 без изменения расчёта стоимости.

`svc_connect` — отдельный признак наличия l4con. Online терминала без него не разрешает консоль. Команда не направляется в оффлайн.

## Сертификаты

`certificate_summary` делает агрегирующий SQL-запрос по tenant. `inspect_terminals` требует точные номера или ограниченный диапазон и отдаёт до 20 терминалов на страницу с состоянием сертификата и PIN. `issue_certificate_pins` принимает максимум пять существующих терминалов. Истёкший сертификат может получить PIN без дополнительного подтверждения; действующий, скоро истекающий или неопределённый требует явной фразы подтверждения от пользователя с точными номерами. Выдача делегирована штатному endpoint MenuBuilder с действующей политикой оплаты и сроком PIN. Для отсутствующих номеров MCP направляет на создание терминала на сайте или к администратору.

## Конфигурация и выпуск

Потребуются приватные переменные `L4MCP_MENUBUILDER_API_URL` (внутренний адрес backend для контейнера L4mcp) и `L4MCP_URL` (внутренний адрес L4mcp для MenuBuilder). Контейнер L4mcp также использует приватный env MenuBuilder для БД и внутренней авторизации IoT. Значения не хранятся в Git. Новых таблиц/миграций нет: используются существующие `api_tokens`, `terminals`, `certificate_pins` и штатные console sessions. `ProcessingBackend` остаётся владельцем Alembic; код MCP вынесен из него.

Перед production-включением проверить: выдачу/отзыв токена каждой роли; отказ role 2/4; отсутствие `sys`, offline и `svc_connect=false`; успешную короткую команду и освобождение аренды; начисление console usage; выдачу 1–5 PIN и отказ на шестом; работу frontend инструкций. Старый контейнер MCP выводится после успешного переключения маршрута.
