Создать веб-приложение для того, чтобы терминалы делали запрос на сервер и получали с сервера пинкоды

Формат запроса: 

... function=reqpincodes&qtty=1&pintype=0

Ответ:

<qtty>1</qtty>

<pincodes>

<pin>55555-55555</pin>

...

</pincodes>

 

Структура БД: 

1) tb_Hotspotpincodes

id (целое)

pintype (строка) умолчание = 0

pincode (строка)

pinstate (строка) умолчание = 0

kioskid (целое) умолчание = 0

 

2) ts_Pintype

id

Description

Заполнить записями:

0 Тип по умолчанию

1 Один час

2 Четыре часа

3 Восемь часов

4 Сутки

5 Трое суток

6 Неделя

7 Месяц

 

3) ts_Pinstate

id

Description

Заполнить записями:

0 Новый

1 Кэширован

2 Использован

 

Алгоритм:

При получении запроса приложение сервера извлекает из БД пинкоды в количестве &qtty= и с типом &pintype.

Отправляет их в XML-ответе, ставит статус tb_Hotspotpincodes.pinstate = 2, ставит tb_Hotspotpincodes.kioskid = идентификатор киоска, сделавший запрос.

Т.к. пинкодов избыточное количество, то сервер может не контролировать успешность доставки на терминал и всегда при выборке ставить статус "Использован".

Пинкоды будут попадать в базу автоматическим экспортом из файла и это пока за рамками данной задачки.
СЕРВАК для этого веб-приложения будет аналогичен процессингу.


 

Дима, а тебе дополнительно – к этому веб-приложению нужно будет серверок простой с нашим ядром процессинга, сертификатами и АРМами: Терминалы, Пользователи, монтерм, монплат, орги.

3 ТСП в таблице:

1)     Услуги хранения

2)     Пинкоды

3)     Прочие услуги
