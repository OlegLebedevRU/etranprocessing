# Media TLS: обязательный CA-сертификат

## Task intake
- Цель: сохранить исправление media TLS в коде и исключить генерацию self-signed.
- Scope: l4media nginx/Compose/deploy, CI-deployer и документация; без ingress/Janus.
- Владелец: media-nginx владеет серверной TLS-парой; CA выдаёт сертификат.
- Producer → consumer: каноническая CA-пара → read-only mount → nginx → leo4proxy.
- Инварианты: `dev.leo4.ru`, serverAuth, доверенный CA, срок и совпадение ключа;
  fallback IP сохраняет логическое TLS-имя. Ключи остаются на сервере.
- Проверка: позитивный и отрицательные gate-тесты, builder image, production
  проверка только nginx и native TLS probe. Видеокадры отдельно.

## Выполнено
- 2026-10-04: production media self-signed заменён существующим `dev.leo4.ru`
  от `iot.leo4.ru`; цепочка/имя/назначение и ключ проверены, nginx -t/reload прошли.
- Репозиторий: canonical mounts, fail-closed entrypoint и pre-deploy gate,
  безопасное пересоздание только nginx после обновления bind-mounted файлов.
- Старый deploy.sh больше не генерирует сертификат и не собирает на production.

## Проверки и ограничения
- [x] Production openssl verify и соответствие пары перед заменой файлов.
- [x] Production nginx -t и reload только media-nginx.
- [ ] Новые gate-тесты и immutable image: выполняются в текущем выпуске.
- [ ] Runtime нового image и native TLS probe после выпуска.
- [ ] E2E видео/чистая установка 773: отдельно, пользователь запускает l4setup.
- Gate не проверяет CRL/OCSP; обновление файлов не обновляет существующий
  file bind mount автоматически, нужен deploy/reload-media.sh.
- Backup старой пары остаётся на production в закрытом task-run directory для
  отката; секретные данные не перенесены в репозиторий.
