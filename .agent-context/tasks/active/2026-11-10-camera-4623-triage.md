### Minimal implementation plan (no new service, broker, generic queue framework or schema initially)

1. Bound DB operations and worker progress. Configure explicit asyncpg connect/command timeouts and SQLAlchemy pool acquisition timeout for the dedicated worker through existing configuration, preserving existing settings for unrelated consumers. Set worker-session statement/lock limits where needed. Pick measured budgets compatible with10s owner TTL and2s broker confirm; do not blindly timeout a valid16-message batch. Cover acquisition, query, transaction exit and connection cleanup, not only the query body. Preserve cancellation. A timeout/ambiguous commit is not permission to repeat an external command or continue with unverified ownership.
2. Use existing loop for recovery: rollback/discard failed connection, new session next bounded attempt; small capped backoff after transient DB failures, reset after success, rate-limited structured log. Never reset persisted counters/boot retirement. On expiry/loss of owner certainty, retire local clock ownership and use existing fenced epoch takeover; do not resume old START/renew or extend lease deadlines.
3. Fail visibly if cleanup/cancellation cannot finish within a separate grace period: dedicated worker exits nonzero, existing unless-stopped supervisor restarts it. Use a simple local progress deadline/watchdog if coroutine deadlines alone cannot cover wedged cleanup. No need for an independent monitoring service. A Docker unhealthy flag alone is insufficient because restart policy does not restart a live unhealthy process. Log stage and last completed cycle; alert on progress age and oldest queue age.
4. Materialize pending hello within the existing JSONB jobs list, under existing per-SN row lock. Remove expired jobs before capacity check and record bounded expired/superseded results for existing waiters. For equivalent contract/capability context and same SN/boot, retain at most one unprocessed hello; a new enrollment attempt supersedes the queued one. Remove superseded entry then append replacement to preserve receive order relative to other jobs. Exact duplicate must not perpetually refresh TTL. Reject high-water regression; keep the complete chosen payload intact, never synthesize a payload by mixing fields. Do not coalesce distinct boots, pending/completed handshakes, ACK/NACK, START/STOP/renew/readiness or command receipts. Define superseded result semantics explicitly so existing submit waiters finish promptly rather than hang.
5. Receive order is not proven device event order: enrollment_id is UUID, not a sequence. Call the retained item latest-received candidate, not authoritative latest state. Existing challenge/epoch/boot/high-water validation remains authority. Late ACK for superseded attempt must not authorize a new attempt; current pending handshake is never rewritten. If stronger latest-produced semantics are required, that needs a separate protocol change; avoid it in this conservative patch.
6. Keep PostgreSQL as durable authority. During outage commands fail closed with503/504 and retry hint; after recovery processing resumes automatically. Do not claim uninterrupted processing while durable storage is unavailable. Keep existing MQTT handling until ACK/requeue semantics are tested: no new unbounded in-memory buffering and no blindly replayed control requests.
7. MB preserves specific backend codes: actual busy lease →409/session_busy, temporary DB/worker/inbox unavailability →service error, stale gauge →freshness reason. No UI instruction to stop another operator's session for a database outage.
