# l4mcp /IoT: согласованный план пользовательских событий

## Контекст
2026-10-01. Документационная задача: общий план и подробный шаг IoT после
аудита master/runtime. Реализация, миграции, тестовые события и деплой
не выполнялись. Данные и миграция IoT принадлежат его отдельному репозиторию.

## Зафиксировано
- [Основной план](../../../docs/menu_arch-l4mcp-user-events-plan.md):
  IoT → MenuBuilder → l4mcp → сквозная приёмка.
- Пользователь согласовал изоляцию прежней истории при переносе; tenant
  определяется по серверной привязке на момент приёма. Точный момент
  возникновения/миграции не восстанавливаем.
- Старые события без достоверного tenant скрыты из tenant API; текущая
  привязка не используется для автоматического backfill.
- IoT шаг: nullable org_id + индекс, collector, фильтрация всех чтений,
  отдельный read-only search900–999/448 с cursor, документы и negative tests.
- Контракт search — проектируемый, не существующий runtime endpoint.
- Общий offset и прежний incremental lifecycle не используются новым reader.
- MenuBuilder повторно проверяет токен/active tenant/terminal и internal
  mapping, l4mcp связывает команду и события UUID448. Новых MQTT connections
  и native изменений l4con в этом плане нет.

## Проверка / границы
Относительные ссылки плана проверены; docs/index обновлены. Code tests и
runtime не запускались в документационной задаче. Предыдущий audit evidence
не объявляется доказательством работоспособности ещё не реализованного API.
Новых credentials, процессов или внешних артефактов не создавалось.

## Следующее действие
Реализовать шаг IoT от актуального origin/master по правилам его репозитория,
передать проверенный API consumer-контракт MenuBuilder. Выпуск и runtime
переноса — отдельная реализация, на выделенном тестовом устройстве.
