# Руководство пользователя: Развёртывание и администрирование комплекса служб Leo4

Настоящее руководство предназначено для сервисных инженеров, технических специалистов и администраторов платёжных терминалов платформы **etranprocessing**. В документе описан быстрый запуск по принципу **«Запустил и забыл» (Zero-to-Start)**, а также расширенные сценарии настройки, проверки и диагностики.

---

## 1. Раздел «Zero-to-Start» (Быстрый запуск для пользователя)

Комплекс утилит спроектирован так, чтобы установка на чистый терминал выполнялась **в один клик** без ручной настройки служб и реестра.

### 1.1. Состав дистрибутива
Для установки требуется пакет файлов из каталога `tools/dist/`:
1. **`l4install_x64.cmd`** / **`l4install_x86.cmd`** (или `l4install.exe`) — Установщик и диспетчер первичной инициализации с автоматическим запросом прав администратора (UAC Elevation).
2. **`tools.zip`** — Структурированный архив со всеми бинарными файлами, службами и настоящим руководством (`leo4proxy`, `mosquitto`, `l4con`, `l4desk`, `l4sql`, `l4pin`, `l4superv`, `terminal-tools-user-guide.md`).
3. **`ffmpeg.zip`** — Пакет медиадвижка FFmpeg для захвата экрана и RTP-стриминга (статические бинарники x64/x86 Zero-Dependency, манифест контрольных сумм `ffmpeg.sha256`).

> При распаковке в целевой каталог (`C:\l4tools`) руководство пользователя `terminal-tools-user-guide.md` автоматически извлекается в корень каталога рядом с `l4install.exe`.

---

### 1.2. Пошаговая инструкция развёртывания

#### Шаг 1. Копирование файлов
Скопируйте оба файла (`l4install.exe` и `tools.zip`) в **любую временную папку** на терминале (например, `C:\distr\` или на Рабочий стол).
> **Важно**: Оба файла должны лежать в **одной папке** рядом друг с другом.

#### Шаг 2. Запуск установки (1 клик)
Запустите файл **`l4install.exe`** двойным кликом мыши (или из командной строки).
* Появится стандартный системный запрос Windows UAC (Контроль учётных записей) на повышение прав — нажмите **«Да»**.
* Установщик выполнит все действия автоматически:
  1. Создаст целевой каталог **`C:\l4tools\`** (папка по умолчанию).
  2. Распакует все компоненты и утилиты с сохранением структуры.
  3. Зарегистрирует и запустит системные службы Windows:
     - `Leo4Proxy` — mTLS-прокси и источник метаданных.
     - `Mosquitto` — Локальный MQTT-брокер (в режиме Standby).
     - `L4Con` — Агент удалённой веб-консоли.
     - `L4Superv` — Системный супервизор и сторожевой таймер (Watchdog).
  4. На экране отобразится финальное сообщение: `[SUCCESS] Leo4 Tools Suite installed and running!`

#### Шаг 3. Первичный выпуск сертификата по PIN-коду
Если у вас есть выданный администратором PIN-код (например, `721023`), выполните в командной строке:
```cmd
C:\l4tools\l4pin\l4pin.exe 721023
```
* `l4pin` сгенерирует неэкспортируемый ключ в защищённом хранилище Windows CNG, получит подписанный сертификат и установит его в `LocalMachine\MY`.
* Служба `leo4proxy` мгновенно активирует mTLS-туннель.
* Супервизор `l4superv` перестроит конфигурацию `Mosquitto` в боевой режим и активирует онлайн-связь терминала с сервером.

**Готово! Комплекс полностью настроен и функционирует в автономном режиме.**

## 2. Раздел для продвинутого использования и администрирования

### 2.1. Опции командной строки `l4install.exe`

Установщик поддерживает гибкие параметры для автоматизированных систем деплоя:

```cmd
l4install.exe [ОПЦИИ]
```

| Параметр | Короткий | По умолчанию | Описание |
|---|---|---|---|
| `--dest <dir>` | `-d` | `C:\l4tools` | Каталог установки комплекса утилит. |
| `--zip <file>` | `-z` | `./tools.zip` | Путь к архиву с инструментами. |
| `--ffmpeg-zip <file>` | — | `./ffmpeg.zip` | Путь к архиву с медиадвижком FFmpeg. |
| `--skip-ffmpeg` | — | `false` | Пропустить распаковку и установку FFmpeg. |
| `--silent` | `-S` | `false` | Тихий режим без вывода текстовых баннеров в консоль. |
| `--no-services` | `-n` | `false` | Только распаковать файлы без регистрации и запуска служб. |
| `--help` | `-h` | — | Вывод справки по параметрам. |

**Примеры использования**:
```cmd
:: Установка в нестандартную папку
l4install.exe --dest D:\apps\l4tools

:: Автоматическая тихая установка через скрипт деплоя
l4install.exe --dest C:\l4tools --silent
```

### 2.2. Управление и команды супервизора `l4superv.exe`

Супервизор расположен в `C:\l4tools\l4superv\l4superv.exe` и поддерживает команды управления:

```cmd
l4superv.exe [КОМАНДА]
```

| Команда | Описание |
|---|---|
| `--status` | Выводит текущий статус всех служб комплекса и снимок оркестратора (`state.json`). |
| `--check` | Выполняет один такт синхронизации конфигураций и проверки служб, затем завершает работу. |
| `--console` (`-f`) | Запуск супервизора в интерактивном режиме консоли (удобно для отладки). |
| `--install` (`-i`) | Регистрация `l4superv` как службы Windows SCM (`L4Superv`, автозапуск `SERVICE_AUTO_START`). |
| `--uninstall` (`-u`)| Остановка и удаление службы `L4Superv` из системы. |
| `--start` | Запуск службы `L4Superv`. |
| `--stop` | Остановка службы `L4Superv`. |
| `--restart` | Перезапуск службы `L4Superv`. |

### 2.3. Конфигурационный файл `l4superv.json`

Файл `l4superv.json` находится в корне базового каталога (`C:\l4tools\l4superv.json`). Если файл отсутствует, используются безопасные встроенные значения по умолчанию.

```json
{
  "base_path": "C:\\l4tools",
  "proxy_url": "http://127.0.0.1:18443/_leo4/info",
  "poll_interval_sec": 15,
  "watchdog_interval_sec": 10,
  "watchdog_enabled": true,
  "mosquitto_port": 1883,
  "auto_reset_on_clone": true,
  "services": {
    "leo4proxy": { "auto_start": true },
    "mosquitto": { "auto_start": true },
    "l4con":     { "auto_start": true }
  }
}
```

* `poll_interval_sec` — Частота проверки метаданных сертификата в `leo4proxy` (по умолчанию 15 сек).
* `watchdog_interval_sec` — Частота проверки состояния процессов Windows (по умолчанию 10 сек).
* `watchdog_enabled` — Включение автоматического перезапуска упавших служб.
* `auto_reset_on_clone` — Защита от клонирования диска (автоматический сброс в Standby при несовпадении `hw_fingerprint`).

### 2.4. Кастомизация шаблона Mosquitto (`mosquitto.conf.tmpl`)

Если вам требуется добавить специфические параметры брокера (например, кастомные порты, настройки TLS, логирование), поместите файл `mosquitto.conf.tmpl` в каталог `C:\l4tools\`.

Супервизор поддерживает следующие макропеременные в шаблоне:
* `%SN%` — Подставляет активный серийный номер устройства (например, `a4b0000773c82116d210826`).
* `%BASE_PATH%` — Подставляет базовый путь с прямыми слэшами (например, `C:/l4tools`).
* `%PORT%` — Подставляет локальный порт MQTT (по умолчанию `1883`).

При изменении состояния супервизор автоматически перезаписывает `C:\l4tools\mosquitto\mosquitto.conf` на основе шаблона и перезапускает службу.

### 2.5. Механизм защиты от клонирования диска (Anti-Clone Protection) и работа с хранилищем сертификатов

#### 1. Как работает защита от клонирования
При первом успешном связывании сертификата супервизор снимает стабильный аппаратный отпечаток хоста (`HW Fingerprint`):
$$\text{HW Fingerprint} = \text{MachineGuid} + \text{VolumeSerialNumber}(C:\backslash)$$
Значение отпечатка сохраняется в файле `state.json`.

Если системный образ диска был скопирован на другой терминал (клонирование через Acronis/Clonezilla/VM) или если папка с утилитами была скопирована вместе со старым `state.json`:
1. `l4superv` фиксирует несовпадение аппаратного отпечатка с сохранённым в `state.json`.
2. Если в `l4superv.json` включён параметр `"auto_reset_on_clone": true` (по умолчанию включён), активируется **режим защиты от несанкционированного переноса**:
   - Вызывается процедура очистки: сертификаты терминала (содержащие в Subject или Email домены `leo4.ru` или `forpay.ru`) **автоматически удаляются** из системного хранилища `LocalMachine\MY`.
   - `mosquitto.conf` сбрасывается в изолированный локальный Standby-режим.
3. Терминал переходит в безопасное ожидание ввода собственного PIN-кода через `l4pin`. Это исключает конфликт сессий и перехват управления в облаке.

> **Рекомендация для инженеров:**
> - При установке нового терминала всегда используйте `l4install.exe` или копируйте дистрибутив **без** файла `state.json` (инсталлятор создаст корректный `state.json` для текущего железа).
> - Если требуется отключить автоматическое удаление сертификатов при несовпадении отпечатка, установите в `l4superv.json` значение `"auto_reset_on_clone": false`.

#### 2. Параллельный доступ к хранилищу сертификатов (Отсутствие блокировок)
- Служба `leo4proxy` выполняет периодический опрос сертификатов с использованием стандартных интерфейсов Windows CryptoAPI (`CertOpenStore`, `CertEnumCertificatesInStore`, `CertCloseStore`).
- Данные вызовы работают в режиме разделяемого кэша реестра Windows (Shared Read-Only) и **не устанавливают эксклюзивных монопольных блокировок**.
- Поллинг сертификатов полностью прозрачен и безопасен для работы основного терминального ПО, служб Schannel, IIS и системных оснасток (`certmgr.msc` / `certlm.msc`).

### 2.7. Работа с базой данных терминала через `l4sql`

В комплекс входит нативная утилита **`l4sql`** (`C:\l4tools\l4sql\l4sql.exe`), предназначенная для безопасного выполнения диагностических SQL-запросов из удалённой консоли `l4con` или локального терминала:

* **Автообнаружение параметров БД**: автоматический поиск активной папки ПО (`D:\Platerra...`), выбор свежего лога и чтение `DBConfig.xml`.
* **Авторизация**: прозрачная Windows-аутентификация текущего пользователя (Trusted Connection).
* **Безопасность (Read-Only Guard)**: блокировка любых модифицирующих DML/DDL команд (`UPDATE`, `INSERT`, `DELETE`, `DROP`, `ALTER`, `TRUNCATE`, `SELECT INTO`).
* **Разрешённые хранимые процедуры**: выполнение процедур разрешено только с префиксом `l4_` (`EXEC l4_...` или `EXEC dbo.l4_...`).
* **Быстрые шорткаты и лимиты**:
  ```cmd
  # Просмотр таблицы (по умолчанию лимит 100 строк)
  l4sql tb_Variables

  # Запрос с лимитом строк
  l4sql --limit 20 tb_Variables

  # Вывод в формате JSON
  l4sql --json --limit 5 tb_Variables

  # Произвольный SQL запрос
  l4sql "SELECT Id, Name, Value FROM tb_Variables WHERE Name LIKE 'sys%'"
  ```

### 2.8. `l4desk` — Удалённое управление мышью

Агент **`l4desk`** (`C:\l4tools\l4desk\l4desk.exe`) предназначен для безопасного удалённого перемещения курсора и выполнения левых кликов мыши на терминале оператором из интерфейса видеонаблюдения `MenuBuilder`.

#### 1. Особенности запуска в пользовательской сессии
В отличие от фоновых служб Windows (Session 0), `l4desk` автоматически запускается супервизором `l4superv` в **активной интерактивной сессии пользователя** (Session ≠ 0). Это необходимо для доступа к рабочему столу терминального ПО (`winsta0\default`) и выполнения Win32 API `SendInput`.

#### 2. Как убедиться, что агент онлайн:
- **Через CLI супервизора**: выполните команду `C:\l4tools\l4superv\l4superv.exe --status`. В блоке служб должна присутствовать строка:
  ```text
  l4desk       : RUNNING      (pid 1234, session 1)
  ```
- **В диспетчере задач**: процесс `l4desk.exe` запущен от имени залогиненного пользователя терминала с номером сессии `Session > 0`.
- **В веб-панели MenuBuilder (`/video`)**: при выборе терминала отображаются зелёные индикаторы:
  - `Агент: online`
  - `Экран доступен`
- **В лог-файле**: `C:\l4tools\l4desk\log\l4desk.log` фиксирует успешное подключение:
  ```text
  [OK] MQTT Connected successfully (rc=0)
  Published presence [online]: {"v":1,"type":"presence",...}
  ```

#### 3. Что делать при сообщении «Экран заблокирован» (`desktop_locked`):
- **Причина**: Активный десктоп заблокирован операционной системой Windows (экран блокировки `Winlogon`, заставка-скринсейвер, либо активен системный запрос UAC на защищённом столе `Secure Desktop`). В целях безопасности Windows запрещает программную инъекцию ввода в заблокированные десктопы.
- **Действия оператора/инженера**:
  1. Разблокируйте терминал (автоматический или ручной вход в учётную запись киоска).
  2. Завершите окно запроса прав администратора (UAC).
  3. Как только активным станет рабочий стол `"Default"`, `l4desk` автоматически пересчитает статус и в течение 5 секунд переведёт индикатор в веб-панели в состояние `Экран доступен`.

### 2.9. Диагностика и устранение неполадок (Troubleshooting)

1. **Службы не запускаются**:
   * Проверьте наличие прав администратора.
   * Убедитесь, что антивирусное ПО не блокирует запуск бинарных файлов из `C:\l4tools\`.
2. **Проверка сетевых портов на терминале**:
   * `1883` — Локальный MQTT порт брокера (должен слушать `127.0.0.1`).
   * `18883` — Внутренний порт mTLS моста `leo4proxy` (активен только при наличии валидного сертификата).
   * `18443` — HTTP эндпоинт метаданных `leo4proxy` (доступен всегда: `curl http://127.0.0.1:18443/_leo4/info`).
   * `443` — Внешний порт Reverse Proxy на `leo4proxy`.
   * `7001` / `7002` — Порты удалённой веб-консоли `l4con`.
3. **Анализ лог-файлов**:
   * Лог брокера: `C:\l4tools\mosquitto\log\mosquitto.log`.
   * Системные события: Просмотр событий Windows (`eventvwr.msc` -> Журналы Windows -> Приложение / Система).
4. **Пропал сертификат после переноса папки или развёртывания образа (Anti-Clone Auto-Reset)**:
   * **Причина**: `l4superv` обнаружил несовпадение аппаратного отпечатка текущей ОС с отпечатком в `state.json` и выполнил процедуру защиты от клонирования, удалив терминальные сертификаты из `LocalMachine\MY`.
   * **Решение**: выпустите новый сертификат через `C:\l4tools\l4pin\l4pin.exe <PIN>` или удалите файл `state.json` перед переносом папки на новое железо. При необходимости отключите автосброс (`"auto_reset_on_clone": false` в `l4superv.json`).
5. **Вопрос о блокировке хранилища сертификатов (Store Lock)**:
   * Поллинг сертификатов службами `leo4proxy` и `l4superv` не захватывает эксклюзивных дескрипторов хранилища Windows и не препятствует чтению сертификатов сторонними процессами и платёжными программами.
6. **Повторный выпуск сертификата**:
   * Если сертификат отозван или заменён на сервере, запустите:
     ```cmd
     C:\l4tools\l4pin\l4pin.exe <НОВЫЙ_PIN>
     ```
   * Комплекс автоматически применит новый сертификат без перезагрузки операционной системы.
