# Проверка документационного экспорта L4D-17D media

Статус: `VERIFIED` для документального экспорта. Runtime и серверы в этой
работе не изменялись и не проверялись повторно.

## Основание и конечный scope

Поручение пользователя: разрешить блокировку каскада в media handoff.
Контроллер использовал §10.1 `PROMPT-STANDARD.md`: отдельный data-only
экспорт в `l4desk-service` для consumer 17E. Исходные принятые записи и
отчёт 17D не изменялись.

Проверены только отчёт `l4media/docs/l4desk/handoffs/L4D-17D-MEDIA-report.md`
и шесть путей из таблицы `contract.md` на Git commit `85cd644`.
Код не исполнялся. Сверены Git/raw SHA-256, совпадение blob с исходными
коммитами `37adfd0`/`fe9dcd1` и причина расхождения старых SHA-256:
LF → CRLF даёт точное совпадение 6/6. SHA-256 отчёта —
`3112ee34919e8ef6ceeb4d6d935e2af275dfc07f23012a2afc055192a9f700c0`.

## Предел доказательства

Пакет передаёт историческое evidence 17D и опубликованные байты источников.
Заявленные старым отчётом 21 тест и production smoke здесь не запускались;
актуальное состояние media-контейнеров и совместимость после более поздних
коммитов требуют отдельной проверки при приёмке 17E. Этот экспорт не
заменяет runtime DEPLOYED handoff и не открывает 17F сам по себе.

После публикации `contract.md` и этого отчёта контроллер отдельно сверяет
remote commit и SHA-256 обоих опубликованных файлов и только затем добавляет
новый append-only `ACCEPTED` handoff с `deployment_status: DOCS_PUBLISHED`.
