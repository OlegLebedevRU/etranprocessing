# Проверка документального экспорта 17A–17C

Статус: `VERIFIED` только для data-only экспорта. Runtime, исходники трёх
проектов и серверные файлы в этом шаге не менялись и не проверялись.

## Task intake

- Цель / тип: подготовить предметный документальный вход для корректирующего 17F.
- Scope и владелец: `l4desk-service`, контроллер каскада; источник — принятый
  `contract-handoff.md` в Git commit
  `2ad0c8b868a092143f3e36a3719238b3a31aa17f`.
- Producer → consumer: три исторических handoff 17A/17B/17C → этот
  immutable data-only экспорт → `L4D-17F-DOCS-FIX-01`.
- Инварианты: старые `ACCEPTED` блоки не меняются; их отсутствующие digest
  не восполняются догадкой; исторические тесты не выдаются за новые.
- Проверка: уникальность и статус трёх исходных блоков, SHA-256 их сырых
  Git-байтов и совпадение экспортированных YAML-снимков.

## Проверенные байты

Для каждого ID из таблицы извлечён участок от точного
`<!-- HANDOFF:<ID>:BEGIN -->` до точного `<!-- HANDOFF:<ID>:END -->`
включительно из `git show
2ad0c8b868a092143f3e36a3719238b3a31aa17f:l4desk-service/docs/prompts/contract-handoff.md`.
Каждый маркер встречается ровно один раз, `status: ACCEPTED`; внутри
нет `artifact_paths` и `artifact_sha256`. YAML внутри участка побайтно
перенесён в `contract.md`, за исключением оформления Markdown вокруг блока.

Краткие исторические результаты тестов и smoke в `contract.md` взяты из
прозы того же принятого журнала рядом с исходными блоками. Полный SHA

и здесь не расширялся до полного SHA. Исходные отчёты этих проектов не
открывались, поэтому экспорт не утверждает их побайтовую тождественность.

## Предел доказательства и публикация

Это проверка содержания принятого журнала, не новая приёмка Agent,
ProcessingBackend или IoT. В частности, текущие image, schema, Agent
package, OpenAPI и terminal runtime должны быть сверены при black-box 17F.
Для documentation-only шага Python/frontend suites и деплой не требуются.

После commit/push этих двух файлов контроллер отдельно сверяет удалённый
commit и Git/raw SHA-256 обоих артефактов, затем добавляет новый
append-only `ACCEPTED` handoff со статусом `DOCS_PUBLISHED`. Старые
handoff остаются без изменений.
